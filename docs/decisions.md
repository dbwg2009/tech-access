| 2026-11-15 | Pi hub static IP `10.102.40.10/16` on `eth0` (Control subnet), hostname `tech-hub`, no gateway. `10.102.40.x` becomes the access-control block (boxes from `10.102.40.101`). | Third octet = device type in the IP scheme; `40` is unused and outside the DHCP pool and all reserved ranges. |
| 2026-11-15 | Day pass level lives in a new optional `Level` column on the `Fobs` sheet (1–4, blank = 1). Read only for `Day pass` fobs. | Fixed-level day passes need a place to store the level; optional so the existing Sheet still imports. |
| 2026-11-15 | An `Active` `Day pass` fob may have a blank Person ID (guest). Blank is still an error for `Standard` and `Admin` fobs. | Guests aren't on the People sheet. |
| 2026-11-15 | Rows missing from an applied import are archived (`archived_at`; people → Left, fobs → Revoked), not hard-deleted. Archived rows are left out of export and the diff; re-adding the ID un-archives it. | The format prefers marking over deleting, but a row that's still exported would come back as a "removal" on every import. Archiving keeps the event history intact and the round trip clean. |
| 2026-11-15 | `.xlsx` library: SheetJS Community Edition 0.20.3, vendored as `hub/vendor/xlsx-0.20.3.tgz` (sha256 `8dc73fc3…99fe8`) and pinned in `bun.lock` with its integrity hash. | No dependencies, maintained, works under Bun with buffers. The npm `xlsx` package is stale, and ExcelJS's last stable release was 2023 with nine dependencies. Vendoring means installs don't need cdn.sheetjs.com, so the hub can still be rebuilt after 2028 if that CDN goes away. Trade-off: exported files have no styling or dropdowns. |
| 2026-11-15 | First import (bootstrap): when the hub has no Active Admin fob at all, an Active Admin fob listed in the workbook being applied may authorise it, as long as its person is Active. After that, only Admin fobs already in the hub can apply. | An empty hub has no admin fob to tap. Logged as `bootstrap: true` on the `import_applied` event. |
| 2026-11-15 | Import: enum values match case-insensitively and are stored in the canonical spelling. A preview is refused (409) if the hub's data changed since it was made, or if a newer workbook was uploaded. | Forgiving of typing, strict about applying exactly what the admin saw. |
| 2026-11-15 | Export writes dates as real date cells formatted `dd/mm/yyyy`, UIDs and IDs as text cells (so leading zeros survive), and logs an `export` event. | Readable in UK spreadsheets; round trips through the importer. |
| 2026-11-15 | an Active `Admin` fob opens every box and takes any kit, whatever the level or specialism, and "disable all students" doesn't affect it. Its person (if any) must still be Active. | The admin fob is the master key (Daniel, Mrs Ritter, sealed spare). |
| 2026-11-15 | staff and hire techs match any kit specialism, as well as counting as Level 4. A guest day pass (no person) has no specialism, so it only takes `Any` kit. | Consistent with "staff and hire techs open everything". Guests shouldn't take specialist kit. |
| 2026-11-15 | TECHSOFTWARE needs an Admin fob or a `Standard` fob of a Level 3+ student or a staff member. Hire techs and day passes can't, even at Level 4. "Disable all students" applies. | Software updates are a crew/staff job, not a visitor's. |
| 2026-11-15 | A student with a blank Level is refused everywhere ("No level set"), even for boxes with no Required level. The importer warns about it. | Fobs are issued at Level 1, so a blank Level is a data mistake, not a choice. |
| 2026-11-15 | `show_mode` has no effect on access yet (superseded 2026-11-16). | Not defined in the brief. To decide with the panel in weeks 3–4. |
| 2026-11-15 | The Pi serves NTP (chrony, `local stratum 10`) to `10.102.0.0/16` so lock boxes get the time from the hub. `rtcsync` keeps the RTC in step. The RTC cell charges at 3.0 V (`dtparam=rtc_bbat_vchg=3000000`, from the Raspberry Pi RTC docs). | There's no NTP on the show network. Box logs need sensible times. |
| 2026-11-15 | Hub TLS certificate: RSA 2048, valid 825 days (iOS's limit for certificates from a user-installed CA), renewed automatically 60 days before expiry by a monthly systemd timer. CA: RSA 3072, valid 20 years, key only on the Pi and TECHBACKUP. | The iPad keeps working past 2028 without anyone re-issuing certificates or profiles. |
| 2026-11-15 | MQTT: boxes log in with their Box ID as the username and are limited to `box/<Box ID>/#` by an ACL pattern. One password per box, made by `pi/mqtt-add-box.sh`. The hub user can use every topic. | A box that leaks its password can't pretend to be another box. |
| 2026-11-15 | Hub runs as system user `techaccess` from `/opt/tech-access`, port 8080, database in `/var/lib/tech-access`. Automatic apt upgrades and the apt timers are off. `pi/config.env` is committed (no secrets); passwords and keys live only in `/etc/tech-access`. | Nothing changes on the Pi without someone running a script. Every config is in the repo. |
| 2026-11-16 | Desk panel fob reader: a PN532 on the Pi's GPIO UART in HSU mode, powered from 3.3 V. No buzzer or LED: all feedback is on screen. | Daniel's choice. One reader, wired straight to the Pi; the screen is the feedback. |
| 2026-11-16 | Panel screen: Waveshare 10.1" HDMI + USB touch, landscape 1280×800, dark theme always. | Daniel's choice. Matches the parts list. |
| 2026-11-16 | The panel screen turns off when nobody is using it and wakes on a fob tap or a touch. The touch that wakes it doesn't also press what's under the finger (wake guard). | Daniel's choice. |

| 2026-11-16 | Desk reader device: `/dev/ttyAMA0` (Pi 5 `UART0` on GPIO14/15), turned on with `dtparam=uart0=on`. | 2026-11-16 | PN532 polling: `InListPassiveTarget` (one target, 106 kbps type A) every 150 ms, after setting `RFConfiguration` MaxRetries (`MxRtyPassiveActivation = 2`). `GetFirmwareVersion` every 30 s as a health check. | The default retry is "forever", so the command would never report "no card" and the hub couldn't tell a held fob from a new tap. One command beyond the brief's list. |
| 2026-11-16 | Debounce: a UID is a new tap if it differs from the fob on the reader, or the same fob returns after 600 ms away. | One fob held = one tap; one missed poll doesn't cause a second tap; tapping again after lifting it does. |
| 2026-11-16 | Reader failures are cheap: errors close the port and retry with back-off (1, 2, 5, 10, 30 s, then every 30 s), logged once per distinct problem. `/api/health` reports the reader and stays 200 when it's missing. | Hard rule: a reader problem must never stop the hub or the boxes. |
| 2026-11-16 | Fake reader: `fake_reader = true` adds `POST /api/dev/tap {uid}`, `POST /api/dev/tap-next` (cycles `fake_fobs`) and `GET /api/dev/fobs`, loopback only. With `fake_reader = false` these routes don't exist (404). | Development without hardware; nothing a show-network client could use. |
